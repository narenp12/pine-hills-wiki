# Design: Pine Hills Wiki — Migrate from Quartz 5 to Astro (Starlight + Wikipedia skin)

- **Date:** 2026-08-29
- **Status:** Draft for review
- **Author:** Hermes Agent (brainstorming session)
- **Decision (user-approved):** Astro foundation = **Astro + Starlight (default docs theme) + a custom Wikipedia skin** (no Obsidian/wiki theme dependency). Look = **faithful Wikipedia clone**. Wikilinks resolved by **our own remark-based resolver**. Scope of this session = write spec, stop for approval.

---

## 1. Summary

Replace the current **Quartz 5** static site generator with **Astro** as the build engine, using **plain Astro + content collections** (no third-party wiki theme) and a **custom Wikipedia-style skin** we author ourselves. The wiki content (Markdown in `content/`) and the data pipeline (`scripts/extract.py` → `raw/<year>.json` → `scripts/generate.py` → Markdown) are preserved; only the *engine* and *styling* change. Because plain Astro does not resolve Obsidian-style `[[wikilinks]]`, we ship **our own remark resolver** that maps `[[Title]]`/`[[Title|label]]` to real page URLs.

The single biggest engineering task is resolving the **59 `[[wikilinks]]`** (Obsidian-style), which Quartz handles natively but plain Astro does not. Research shows no Astro *theme* ships wikilink resolution (the nearest, `starlight-theme-obsidian`, lists it as an unmerged feature request and needs a separate plugin that is known to break Starlight's docs loader). So we resolve links ourselves with a remark plugin (`@portaljs/remark-wiki-link` or a small custom one) and author the Wikipedia look as a CSS skin — no third-party wiki theme needed.

## 2. Goals

- Keep the site a "Wikipedia of the Pine Hills Fantasy Football League" in both behavior and look.
- Preserve 100% of existing content and its internal links (no broken `[[...]]`).
- Keep the existing GitHub Pages deploy at the same base path (`/pine-hills-wiki`) and same domain (`narenp12.github.io`).
- Keep the Python + Rust data pipeline working with minimal change (only repoint its Markdown output dir).
- Gain: better search, autogenerated sidebar nav, MDX, and a maintainable, framework-standard base (Astro 6).

## 3. Non-goals (YAGNI for this pass)

- No database, no CMS, no auth, no editing UI. Still Markdown-in-git.
- No reader-mode plugin, OG-image automation, or RSS (can be added later; Starlight supports them).
- No content rewrites — we migrate structure/style, not the prose.
- No change to the Yahoo/FF data extraction approach.

## 4. Current state (brief)

- Engine: **Quartz 5** (`quartz/`, `quartz.config.yaml`). Node 22 locally, Node 24 in CI.
- Content: `content/{teams,seasons,records,lore,rosters,draft}/` + `content/index.md`. Frontmatter carries `title`, `description`, and sometimes `season`/`year`.
- Authoring helper: `scripts/generate.py` emits Markdown with a `wikilink(title, label)` helper → `[[Title]]` / `[[Title|label]]`.
- Deploy: `.github/workflows/deploy.yml` runs `npx quartz build` and uploads `public/` to GitHub Pages.
- 59 wikilink usages need to keep resolving after the move.

## 6. Foundation choice & rationale

**Chosen: Astro + Starlight (the official default docs theme) + a custom Wikipedia CSS skin + a self-owned wikilink resolver.**

- Starlight gives, for free: content collections (typed Markdown/MDX), full-text **search** (Pagefind), **sidebar** nav, **TOC**, **breadcrumbs**, **dark mode**, and overridable components. We use it purely as a layout foundation — we are NOT using `starlight-theme-obsidian` or its (unmerged) wikilink feature.
- The Wikipedia *look* is achieved with a CSS skin (`src/styles/wikipedia.css`) + a few component overrides (header bar, sidebar, `<Infobox>`). No third-party wiki theme = no bus-factor risk.
- Wikilinks are resolved by a **remark plugin** we configure/own (see §10.3) added to `markdown.remarkPlugins`, not by Starlight.

**Why not a wiki theme:** searched — no Astro theme provides working `[[wikilink]]` resolution + Wikipedia styling together. `starlight-theme-obsidian` is Obsidian-publish styled and its wikilink support is an open, unmerged feature request; wiring the community `starlight-obsidian` plugin into it is reported to break Starlight's content loader. Adding it would cost more than it saves.

**Alternatives considered (rejected):**
- *Starlight + `starlight-theme-obsidian`* — theme is single-maintainer and lacks working wikilinks (issue #10); defeats the purpose.
- *Bare Astro + hand-rolled everything incl. resolver from zero* — more work than adopting `@portaljs/remark-wiki-link`; prefer the maintained plugin.

## 7. Wikipedia visual skin (design spec)

Override the default Astro/Starlight look via `src/styles/wikipedia.css` + a few component overrides. Target the recognizable Wikipedia "Vector" aesthetic:

- **Typography:** serif body & headings (Wikipedia uses *Linux Libertine*; we fall back to `Georgia, "Times New Roman", serif`). Monospace only for code.
- **Top header bar:** site title "Pine Hills Fantasy Football League" with a small logo/wordmark on the left, Search box on the right — styled like Wikipedia's top bar (thin border, white bg, subtle shadow).
- **Left rail ("toolbox"):** repurpose Starlight's left sidebar into a Wikipedia-like navigation block — "Navigation" (Seasons, Teams, Records, Draft, Lore) + "Interaction" (GitHub, Yahoo League). Styled as plain text links with section headings, not a card.
- **Article area:** centered, max-width ~860px, serif, with the page title as an `<h1>` separated by a horizontal rule (Wikipedia signature). First paragraph lead styled normally.
- **Right-rail infobox:** floated right, bordered, light-gray header background (`#eaecf0`), key–value rows — see §8.
- **Citations:** footnote references render as superscript; hover shows the citation text (CSS tooltip on the `<sup>`/reference). Implemented with a small `Citation` component or styled standard footnotes.
- **Footer:** "This page was last edited …" style line + GitHub/Yahoo links (reuse Quartz footer links).

Color palette stays neutral (Wikipedia's near-white `#f6f6f6` panels, `#202122` text) with the league accent (current blue `#0d47a1`) reused for links/headings underline.

## 8. Components to build

1. **`<Infobox>` (MDX-importable `.astro`)** — the core Wikipedia element.
   - Props: `title`, optional `image`/`imageCaption`, and a `rows` array of `{label, value}` (values may contain wikilinks/MDX).
   - Renders the floated, bordered table. Used on team pages, season pages, record pages.
2. **`<Citation>` (optional)** — wraps a source with hover tooltip; falls back to styled footnote if skipped.
3. **Header / SiteTitle override** — Wikipedia-style top bar (Starlight supports overriding `Header`/`SiteTitle` components).

Keep it minimal: Infobox + header override + CSS cover ~90% of the "looks like Wikipedia" goal.

## 9. Feature parity map (Quartz → Astro)

| Quartz feature | Astro equivalent | Notes |
|---|---|---|
| `[[wikilinks]]` | `@portaljs/remark-wiki-link` (or custom remark plugin) in `markdown.remarkPlugins` | Resolves `[[Title]]`/`[[Title\|label]]`; build a title→slug permalink map (see §10.3) |
| Search | `@astrojs/pagefind` (or `@astrojs/algolia`) | Add integration; free local search |
| Graph view | *deferred* (not core to Wikipedia look) | Can add later via a component if desired |
| Backlinks | *deferred* | Optional; not in Wikipedia's core UI |
| Sidebar / nav | Starlight `sidebar` config OR a custom `<Sidebar>` | Autogenerate from content tree or hand-author |
| TOC (right) | Starlight `tableOfContents` OR custom TOC | Free with Starlight; custom if bare Astro |
| Breadcrumbs | Starlight breadcrumbs OR custom | Free with Starlight |
| Dark mode | Starlight dark mode OR custom toggle | Optional |
| LaTeX/math | `remark-math` + `rehype-katex` *(optional — no current pages use math; defer unless expected)* | Add to markdown config only if needed |
| Created/modified date | `getLastCommitDate` / file mtime helper | Optional "last edited" line |
| Sitemap | `@astrojs/sitemap` | Add if desired |
| OG image | skip / `astro-og` later | Non-blocking |

## 10. Migration plan (high level — detailed plan is the next step)

1. **Scaffold Astro + Starlight** in a new git branch (e.g. `feat/astro-wiki`); add `@astrojs/starlight`, `@astrojs/pagefind`, and `@portaljs/remark-wiki-link` (math/KaTeX only if later desired — see §9).
2. **Move content:** `git mv content/* src/content/docs/` (keep `.gitkeep` out). Repoint `scripts/generate.py` `CONTENT` → `src/content/docs/`.
3. **Wikilink bridge (critical — validate the resolver against Starlight's loader FIRST):** your 59 `[[...]]` use **display titles with spaces**, e.g. `[[2020 chopstix Post-Draft]]`, not slugs. Quartz resolved these against page *titles/filenames*. Known risk: `@portaljs/remark-wiki-link` dropped naively into Starlight's `markdown.remarkPlugins` is reported to make wikilink pages render empty (Starlight docs-loader friction, datopian/portaljs#1507). Steps:
   - (a) **Prototype first:** on a throwaway branch, confirm the plugin resolves `[[Title]]`/`[[Title|label]]` under Starlight without blanking pages. If it breaks, fall back to a small **custom remark plugin** (≈40 LOC) that rewrites `[[Target|label]]` → `<a href="/slug">label</a>` using a title→slug map. Decide the approach before mass-editing content.
   - (b) **Title ≠ filename.** Actual files are slugged (`teams/chopstix.md`, `seasons/2020-season.md`) while links use titles like `2020 chopstix Post-Draft`. Build a `title → slug` map (from frontmatter `title` + file path) and feed it to the resolver as `permalinks`/`wikiLinkResolver` so `[[2020 chopstix Post-Draft]]` → `/teams/chopstix` (or the generated roster slug).
   - (c) **Forward-reference targets.** Several targets (`* End-of-Season`, `* Post-Draft`, plus `<TEAM>`/`<YEAR>` placeholders in templates) point to pages `generate.py` hasn't created yet. Run `generate.py` before the link-check, or whitelist those targets.
   - **Action:** write a migration script that maps `[[Title|label]]` → the resolver's expected form; add a **tolerant** CI link-check that flags broken links but whitelists not-yet-generated roster pages.
4. **Apply Wikipedia skin:** `src/styles/wikipedia.css` + header/site-title overrides + `<Infobox>` component.
5. **Reconfigure deploy:** `astro.config.mjs` `base: '/pine-hills-wiki'`; update `deploy.yml` to run `npm run build` and upload `dist/`.
6. **Verify** (§12), then cut over `main`.

## 11. Toolchain / config changes

- **`package.json`:** drop `quartz`/plugin scripts; add `dev`/`build`/`preview` (`astro dev|build|preview`). Keep Python/Rust tooling separate. Keep `check`/`format` (tsc + prettier) — point tsc at `astro.config.mjs`/`src`.
- **Remove:** `quartz/`, `quartz.config.yaml`, `quartz.config.default.yaml`, `quartz.ts`, `tsconfig.tsbuildinfo` (Astro supplies its own tsconfig).
- **Add:** `astro.config.mjs`, `content.config.ts`, `src/`.
- **Keep:** `public/`, `scripts/`, `raw/`, `scraper/`, `.github/`, Python `pyproject.toml`/`requirements.txt`.

## 12. Verification / acceptance criteria

- `npm run build` completes with no broken-link warnings; `npm run dev` serves locally.
- All 59 former wikilinks resolve to real pages (automated link-check passes).
- Wikipedia skin visibly applied: serif type, top bar, left toolbox, right infobox on a sample team/season page.
- Search (Pagefind), dark mode, TOC, breadcrumbs all functional. (Graph/backlinks deferred per §9 — not required for Wikipedia look.)
- Math (if later enabled) renders via KaTeX — out of scope until a page needs it.
- Deploys to `https://narenp12.github.io/pine-hills-wiki/` with identical base path; no 404s on known URLs.
- `scripts/generate.py` still produces valid Markdown in `src/content/docs/` and the site rebuilds.

## 13. Risks & mitigations

| Risk | Mitigation |
|---|---|
| `starlight-theme-obsidian` is single-maintainer (bus factor) | Not used — we build on Starlight (official, maintained) + our own skin/resolver. |
| Wikilink resolver breaks Starlight's docs loader (datopian/portaljs#1507) | Prototype the resolver on a throwaway branch before mass edits (§10.3a); fall back to a ~40-LOC custom remark plugin if it blanks pages. |
| Wikilink `title`→filename mismatch breaks links | Build title→slug map; feed to resolver as permalinks (§10.3b); tolerant CI link-check gates cutover. |
| Many wikilink targets are not-yet-generated roster pages | Run `generate.py` before link-check, or whitelist `End-of-Season`/`Post-Draft` targets (§10.3c). |
| Astro 6 / Starlight API drift | Pin versions; follow official Starlight docs for v0.3x `docsLoader`/`docsSchema`. |
| Content missing required frontmatter | Loose collection schema + a generation-time validation pass. |
| KaTeX not configured | No current pages use math (verified); only add `remark-math`+`rehype-katex` if a future page needs formulas. Not a migration risk. |
