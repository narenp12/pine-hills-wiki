# Starlight API reference (Pine Hills wiki)

Saved 2026-08-29 while migrating from Quartz 5 → Astro + Starlight.
Verified against **Starlight 0.41 / Astro 7** (current at time of writing).
Source of truth: https://starlight.astro.build/reference/*

## Integration config (`astro.config.mjs`)

```js
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  base: '/pine-hills-wiki',          // GitHub Pages subpath
  site: 'https://narenp12.github.io',// required for sitemap/abs URLs
  integrations: [
    starlight({
      title: 'Pine Hills Fantasy Football League', // required
      description: '...',
      // social: [{ icon: 'github', label: 'GitHub', href: '...' }], // header icons
      // editLink: { baseUrl: 'https://github.com/.../edit/main/' }, // "edit this page"
      customCss: ['./src/styles/wikipedia.css'], // array of CSS files (local or npm)
      components: { Header: '...', Footer: '...' }, // see Overrides below
      sidebar: [ /* SidebarItem[] — see below */ ],
      // tableOfContents: { minHeadingLevel: 2, maxHeadingLevel: 3 },
      // lastUpdated: true,  // show "last edited" (needs VCS or file mtime)
    }),
    sitemap(),
  ],
  markdown: { remarkPlugins: [/* our wikilink resolver */] },
});
```

### `sidebar` — `SidebarItem[]`
Each item is one of:
- A string shorthand (internal slug), e.g. `'intro'`.
- A link: `{ label, link: '/url' }`.
- An internal link: `{ label?, slug: 'intro' }`.
- A group: `{ label, items: SidebarItem[], collapsed?: boolean }`.
- An autogenerated group: `{ autogenerate: { directory: 'seasons', collapsed?: boolean } }`
  (scans `src/content/docs/<directory>`, sorted alphabetically by filename).

### `customCss`
`string[]` of CSS files relative to project root, or npm-imported CSS
(e.g. `'@fontsource/roboto'`). Loaded after Starlight's base styles.

### There is NO top-level `footer` config key.
Putting `footer: { ... }` in the starlight config throws
`Unrecognized key: "footer"`. Footer content is done via a `Footer` component
override (see below).

## Content collections (new content-layers API, Astro 5+ / Starlight 0.41)

File: **`src/content.config.ts`** (NOT `src/content/config.ts`).

```ts
import { defineCollection } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';
import { z } from 'astro:content';

export const collections = {
  docs: defineCollection({
    loader: docsLoader(),                 // file-based routing from src/content/docs
    schema: docsSchema({
      extend: z.object({
        season: z.number().optional(),
        year: z.number().optional(),
      }),
    }),
  }),
};
```

- Every `.md` / `.mdx` / `.markdoc` file in `src/content/docs/` becomes a page.
- URL = file path without extension; `index.md` → `/`.
- `docsSchema()` provides title/description/sidebar/etc. `extend` with zod for
  custom frontmatter (e.g. `season`, `year`).

## Component overrides

Configure in `starlight({ components: { Name: './src/components/X.astro' } })`.
Full list: https://starlight.astro.build/reference/overrides/

Commonly overridden for this wiki:
- `Header` — top bar (we wrap Starlight's default to add the Wikipedia bar).
- `Footer` — bottom of page. Default renders `<LastUpdated/>`, `<Pagination/>`,
  `<EditLink/>`. Wrap to keep them:
  ```astro
  ---
  import Default from '@astrojs/starlight/components/Footer.astro';
  ---
  <Default><slot /></Default>
  ```
- `Sidebar` — global left nav.
- `PageSidebar` / `TableOfContents` — right-hand TOC.
- `PageTitle` — the `<h1>` (default sets `id="_top"`; preserve it).

### Override gotchas
- Import the default with `import Default from '@astrojs/starlight/components/<Name>.astro'`.
- Page data: `Astro.locals.starlightRoute.id` ('' = homepage),
  `Astro.locals.starlightRoute.entry.data` (frontmatter).
- Reuse built-in components freely; wrap with `<Default><slot /></Default>`.

## Theming / dark mode
- Starlight sets `data-theme="light" | "dark"` on `<html>` (user toggle).
- Declare palette tokens under **both** `:root` and `:root[data-theme='dark']`
  in `customCss` so a toggle doesn't clash (white-on-dark overlap bug).
- Set `color-scheme: light dark;` on `html`.

## MDX
- `.mdx` pages can import components: path is resolved relative to the .mdx file.
  A page at `src/content/docs/teams/x.mdx` imports
  `import Infobox from '../../../components/Infobox.astro';`
  (three `../` to reach `src/`).
- Wikilinks `[[Target|label]]` are resolved by our remark plugin on text nodes,
  including inside MDX component props passed as raw strings.

## Deploy (GitHub Pages)
- `base: '/pine-hills-wiki'` + `site` set.
- Build output is **`dist/`** (not `public/`, which was Quartz's dir).
- Search (Pagefind) is built in — no separate `@astrojs/pagefind` package.
- CI: `node scripts/wikilink-map.mjs` → `npm run build` → upload `dist/`.
